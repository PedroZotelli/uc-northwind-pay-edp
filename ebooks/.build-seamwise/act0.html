Before Act I · How to read this book SEAMWISE
Evidence Discipline · Every claim carries a class

Not every surface carries the same authority

Every page in this book ends with a source line. Its bracketed badges tell you what kind of proof stands behind each claim — so presentation never becomes proof, and released never blurs into current-main.

O Operating
Explicit current ownership or lifecycle rule — OPERATING.md, AGENTS.md.
S Schema
Versioned machine contract — the eight published JSON Schemas.
I Implemented
Executable behavior at the audited current main commit.
T Tested
A local test or adversarial fixture directly exercises the claim.
R Released
Frozen v0.2.0 tag or immutable release artifact.
C Current-main
Implemented after v0.2.0 — not frozen release evidence.
D Documentary
Explanatory prose or presentation copy, checked against code.
X External
Behavior owned by Task-Spec, Converge, a host, or another repository.
P Proposed
Roadmap, design, or model-authored material without implemented proof.
Reading ruleWhere classes disagree, the stricter one wins: schema and implementation outrank prose, and current-main claims are never dressed as released ones.

The master test
Every page answers one of five questions: What evidence allows this cut? · Who owns the resulting boundary? · What observable state proves progress? · Which exact gate prevents an unsafe transition? · Which product owns the next authority? A page that answers none of them does not belong in the book.
