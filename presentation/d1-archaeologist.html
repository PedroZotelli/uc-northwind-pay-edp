Money arrives as files, once a night

The rule of the week

Parsed. Valid. Still wrong.

Run both batches through any ordinary pipeline. Every field-level check passes on both.

batch parses types valid fields legal money agrees
valid-minimal.datB202607230000001 · trailer ends in E ✓ ✓ ✓ ✓
df-source-001.datB202607230000004 · trailer ends in D ✓ ✓ ✓ ✗
3gates pass on both files — and every one of them is telling the truth
every record the right length · every field at its byte offset · D is a legal overpunch character
0fields are malformed — nothing to report at the field level
a parser that checks fields alone cannot see this · there is no bad character to flag
1rule catches it — the one that compares records against each other
layout.yaml · cross_record_rules · trailer net_amount_brl must equal the sum of the rows
where the difference actually lives field checks → cross-record checks → the money field 0 · cross-record 1 · delta 0.01

Green is a claim the parser makes about shape. Correct is a claim only the contract can make about money.

no oracle, no build — a pack that cannot be adjudicated is refused before any modern file exists. Roles · kernel, not a comment

Four roles. Eight zones.
Unix groups

raw-publisher
One-way drop
Can put a file into raw/incoming and nothing else. Cannot watch what happens next.
processor
The Java stage
Takes raw, writes sanitized CSV. Cannot archive — declaring a batch complete is not its decision.
loader
Never sees raw/
Talks to Postgres. Structurally incapable of touching a PAN. That is chown, not a promise.
operator
The widest role
Only role that can archive and see every zone. Write on all eight — not read-only.
